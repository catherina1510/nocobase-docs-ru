# Мультиприложение

## Введение

Плагин **Менеджер мультиприложений** позволяет динамически создавать и управлять несколькими независимыми приложениями без раздельного развёртывания. Каждое подприложение является полностью самостоятельным экземпляром со своей собственной базой данных, плагинами и конфигурацией.

#### Сценарии использования
- **Многоклиентский режим**: предоставление независимых экземпляров приложения, где у каждого клиента свои данные, настройки плагинов и собственная система прав доступа.
- **Главная система и подсистемы для разных бизнес‑доменов**: крупная система, состоящая из нескольких более мелких приложений, развёрнутых и управляемых независимо друг от друга.

::::warning
Плагин «Менеджер мультиприложений» сам по себе не предоставляет возможности совместного использования пользователей.  
Если вам нужно организовать общий пул пользователей между несколькими приложениями, используйте его совместно с **[плагином аутентификации](/auth-verification)**.
::::

## Установка

В менеджере плагинов найдите плагин **Менеджер мультиприложений** и включите его.

![](https://static-docs.nocobase.com/multi-app/Plugin-manager-NocoBase-10-16-2025_03_07_PM.png)

## Руководство по использованию

### Создание подприложения

В меню настроек системы нажмите пункт «Мультиприложение», чтобы перейти на страницу управления мультиприложениями:

![](https://static-docs.nocobase.com/multi-app/Multi-app-NocoBase-10-16-2025_03_48_PM.png)

Нажмите кнопку «Добавить новое», чтобы создать новое подприложение:

![](https://static-docs.nocobase.com/multi-app/Multi-app-NocoBase-10-16-2025_03_50_PM.png)

#### Описание полей формы

* **Название**: идентификатор подприложения, должен быть глобально уникальным.
* **Отображаемое название**: имя подприложения, отображаемое в интерфейсе.
* **Режим запуска**:
  * **Запуск при первом посещении** — подприложение запускается только при первом обращении пользователя по URL.
  * **Запуск вместе с основным приложением** — подприложение запускается одновременно с основным приложением (это может увеличить время запуска основного приложения).
* **Порт**: номер порта, который используется подприложением во время работы.
* **Пользовательский домен**: настройка отдельного поддомена для подприложения.
* **Закрепить в меню**: закрепить пункт входа в подприложение слева в верхней навигационной панели.
* **Подключение к базе данных**: настройка источника данных для подприложения. Поддерживаются три варианта:
  * **Новая база данных** — повторное использование текущего сервиса данных для создания отдельной базы данных.
  * **Новое подключение к данным** — настройка полностью нового сервиса базы данных.
  * **Режим схемы** — создание отдельной схемы для подприложения в PostgreSQL.
* **Обновить**: если в подключённой базе данных используется более старая версия структуры данных NocoBase, она будет автоматически обновлена до текущей версии.

### Запуск и остановка подприложения

Нажмите кнопку **Запустить**, чтобы запустить подприложение.  
> Если при создании был выбран режим *«Запуск при первом посещении»*, подприложение запустится автоматически при первом посещении.  

Нажмите кнопку **Просмотр**, чтобы открыть подприложение в новой вкладке.

![](https://static-docs.nocobase.com/multi-app/Multi-app-NocoBase-10-16-2025_04_00_PM.png)

### Статус подприложений и журналы

В списке вы можете видеть использование памяти и процессора для каждого приложения.

![](https://static-docs.nocobase.com/multi-app/Multi-app-NocoBase-10-21-2025_10_31_AM.png)

Нажмите кнопку **Логи**, чтобы просмотреть журналы работы подприложения.  
> Если после запуска подприложение недоступно (например, из‑за повреждённой базы данных), вы можете использовать журналы для диагностики и устранения проблемы.

![](https://static-docs.nocobase.com/multi-app/Multi-app-NocoBase-10-16-2025_04_02_PM.png)

### Удаление подприложения

Нажмите кнопку **Удалить**, чтобы удалить подприложение.  
> При удалении вы можете выбрать, нужно ли также удалять соответствующую базу данных. Действуйте осторожно, это действие необратимо.

### Доступ к подприложению
По умолчанию доступ к подприложениям осуществляется по адресу вида `/_app/:appName/admin/`, например:
```
http://localhost:13000/_app/a_7zkxoarusnx/admin/
```
Вы также можете настроить отдельный поддомен для подприложения. Для этого нужно направить DNS‑запись домена на текущий IP‑адрес, а при использовании Nginx — добавить соответствующую конфигурацию виртуального хоста.

### Управление подприложениями через командную строку

В корневом каталоге проекта вы можете управлять экземплярами подприложений через командную строку с помощью **PM2**:

```bash
yarn nocobase pm2 list              # Показать список запущенных экземпляров
yarn nocobase pm2 stop [appname]    # Остановить процесс конкретного подприложения
yarn nocobase pm2 delete [appname]  # Удалить процесс конкретного подприложения
yarn nocobase pm2 kill              # Принудительно завершить все запущенные процессы (включая основное приложение)
```

### Миграция данных из старого мультиприложения

Перейдите на страницу управления старым мультиприложением и нажмите кнопку **Перенести данные в новое мультиприложение**, чтобы перенести данные.

![](https://static-docs.nocobase.com/multi-app/Multi-app-manager-deprecated-NocoBase-10-21-2025_10_32_AM.png)

## Частые вопросы

#### 1. Управление плагинами
Подприложения могут использовать те же плагины, что и основное приложение (включая версии), но при этом настраиваются и используются независимо друг от друга.

#### 2. Изоляция баз данных
Для подприложений можно настроить отдельные базы данных. Если вам нужно организовать обмен данными между приложениями, это можно сделать через внешние источники данных.

#### 3. Резервное копирование и миграция данных
В текущей версии резервные копии данных основного приложения не включают данные подприложений (сохраняется только базовая информация о них). Вам нужно отдельно выполнять резервное копирование и миграцию данных внутри каждого подприложения.

#### 4. Развёртывание и обновления
Версия подприложения автоматически обновляется вместе с основной системой, что обеспечивает согласованность версий между основным приложением и подприложениями.

#### 5. Управление ресурсами
Потребление ресурсов каждым подприложением в целом сопоставимо с основным приложением. В текущей версии одно приложение использует порядка 500–600 МБ оперативной памяти.
