# Промежуточное ПО (Middleware)

Промежуточное ПО серверной части NocoBase по сути является **промежуточным ПО Koa**. Вы можете использовать объект `ctx` для обработки запросов и ответов так же, как в Koa. Однако NocoBase работает с логикой на разных бизнес-уровнях, и если размещать все промежуточные обработчики в одном месте, поддерживать их становится сложно.

Поэтому NocoBase делит промежуточное ПО на **четыре уровня**:

1. **Промежуточное ПО уровня источника данных**: `app.dataSourceManager.use()`  
   Влияет только на запросы к **конкретному источнику данных**. Обычно используется для подключений к базе данных, проверки полей и обработки транзакций в рамках этого источника данных.

2. **Промежуточное ПО уровня ресурса**: `app.resourceManager.use()`  
   Работает только для определенных ресурсов. Подходит для логики уровня ресурса: проверка прав доступа к данным, форматирование и т.д.

3. **Промежуточное ПО уровня разрешений**: `app.acl.use()`  
   Выполняется перед проверкой разрешений и используется для проверки ролей и прав пользователя.

4. **Промежуточное ПО уровня приложения**: `app.use()`  
   Выполняется для каждого запроса. Подходит для логирования, общей обработки ошибок и формирования ответов.

## Регистрация промежуточного ПО

Промежуточное ПО обычно регистрируется в методе `load` плагина, например:

```ts
export class MyPlugin extends Plugin {
  load() {
    // Промежуточное ПО уровня приложения
    this.app.use(async (ctx, next) => {
      console.log('App middleware');
      await next();
    });

    // Промежуточное ПО уровня источника данных
    this.app.dataSourceManager.use(async (ctx, next) => {
      console.log('DataSource middleware');
      await next();
    });

    // Промежуточное ПО уровня разрешений
    this.app.acl.use(async (ctx, next) => {
      console.log('ACL middleware');
      await next();
    });

    // Промежуточное ПО уровня ресурса
    this.app.resourceManager.use(async (ctx, next) => {
      console.log('Resource middleware');
      await next();
    });

  }
}
```

### Порядок выполнения

Порядок выполнения промежуточного ПО следующий:

1. Сначала выполняется промежуточное ПО разрешений, добавленное через `acl.use()`.
2. Затем выполняется промежуточное ПО ресурса, добавленное через `resourceManager.use()`.
3. Затем выполняется промежуточное ПО источника данных, добавленное через `dataSourceManager.use()`.
4. В конце выполняется промежуточное ПО приложения, добавленное через `app.use()`.

## Механизм вставки `before` / `after` / `tag`

Для гибкого управления порядком промежуточного ПО NocoBase предоставляет параметры `before`, `after` и `tag`:

- **`tag`**: помечает промежуточное ПО для использования в последующих обработчиках.
- **`before`**: вставляет обработчик перед промежуточным ПО с указанным тегом.
- **`after`**: вставляет обработчик после промежуточного ПО с указанным тегом.

Пример:

```ts
// Обычное промежуточное ПО
app.use(m1, { tag: 'restApi' });
app.resourceManager.use(m2, { tag: 'parseToken' });
app.resourceManager.use(m3, { tag: 'checkRole' });

// m4 будет размещен перед m1
app.use(m4, { before: 'restApi' });

// m5 будет вставлен между m2 и m3
app.resourceManager.use(m5, { after: 'parseToken', before: 'checkRole' });
```

:::tip

Если позиция не указана, порядок выполнения по умолчанию для нового промежуточного ПО такой:
`acl.use()` -> `resourceManager.use()` -> `dataSourceManager.use()` -> `app.use()`

:::

## Пример луковой модели

Порядок выполнения промежуточного ПО соответствует **луковой модели** Koa: первым происходит вход в стек, последним — выход из него.

```ts
app.use(async (ctx, next) => {
  ctx.body = ctx.body || [];
  ctx.body.push(1);
  await next();
  ctx.body.push(2);
});

app.resourceManager.use(async (ctx, next) => {
  ctx.body = ctx.body || [];
  ctx.body.push(3);
  await next();
  ctx.body.push(4);
});

app.acl.use(async (ctx, next) => {
  ctx.body = ctx.body || [];
  ctx.body.push(5);
  await next();
  ctx.body.push(6);
});

app.resourceManager.define({
  name: 'test',
  actions: {
    async list(ctx, next) {
      ctx.body = ctx.body || [];
      ctx.body.push(7);
      await next();
      ctx.body.push(8);
    },
  },
});
```

Примеры вывода для разных маршрутов:

- **Обычный запрос**: `/api/hello`
Вывод: `[1,2]` (ресурс не определен, поэтому промежуточное ПО `resourceManager` и `acl` не выполняется)

- **Запрос ресурса**: `/api/test:list`
Вывод: `[5,3,7,1,2,8,4,6]`
Промежуточное ПО выполняется в соответствии с порядком слоев и луковой моделью.

## Краткое содержание

- Промежуточное ПО NocoBase расширяет промежуточное ПО Koa.
- Доступны четыре уровня: приложение -> источник данных -> ресурс -> разрешения.
- Для гибкого управления порядком выполнения можно использовать `before` / `after` / `tag`.
- Выполнение следует луковой модели Koa и поддерживает композицию и вложенность промежуточного ПО.
- Промежуточное ПО уровня источника данных влияет только на запросы к конкретному источнику, а уровня ресурса — только на запросы к конкретному ресурсу.
