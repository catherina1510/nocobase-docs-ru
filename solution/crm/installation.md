# Руководство по установке

> Текущая версия разворачивается через **восстановление из резервной копии**. В будущих версиях мы можем перейти на **инкрементальную миграцию**, чтобы упростить интеграцию решения в уже существующую систему.

Чтобы вы могли быстро развернуть CRM 2.0 в своём окружении NocoBase, мы предлагаем два способа восстановления. Выберите вариант, который лучше соответствует вашей редакции и технической подготовке.

Перед началом убедитесь, что выполнены условия:

- У вас уже развёрнуто базовое окружение NocoBase. См. [официальное руководство по установке](https://docs.nocobase.com/ru/get-started/quickstart).
- Версия NocoBase **v2.1.0-beta.2 или выше**
- Вы скачали файлы решения CRM:
  - **Файл резервной копии**: [nocobase_crm_v2_backup_260223.nbdata](https://static-docs.nocobase.com/nocobase_crm_v2_backup_260223.nbdata) — для метода 1
  - **SQL-файл**: [nocobase_crm_v2_sql_260223.zip](https://static-docs.nocobase.com/nocobase_crm_v2_sql_260223.zip) — для метода 2

**Важные замечания**:
- Это решение построено на **PostgreSQL 16**. Убедитесь, что в вашем окружении используется PostgreSQL 16.
- **DB_UNDERSCORED не должен иметь значение `true`**: проверьте `docker-compose.yml` и убедитесь, что `DB_UNDERSCORED` не установлен в `true`, иначе восстановление завершится ошибкой.

## Метод 1: восстановление через менеджер резервных копий (рекомендуется для Professional/Enterprise)

Этот метод использует встроенный плагин NocoBase «[Менеджер резервных копий](https://docs.nocobase.com/ru/plugins/@nocobase/plugin-backups/)» (Professional/Enterprise) для восстановления «в один клик». Это самый простой вариант, но у него есть требования к окружению и редакции.

### Ключевые особенности

* **Преимущества**:
  1. **Просто использовать**: полностью через интерфейс; восстанавливает все конфигурации, включая плагины.
  2. **Полное восстановление**: **восстанавливает все системные файлы**, включая шаблоны печати и файлы, загруженные в поля файлов таблиц.
* **Ограничения**:
  1. **Только Professional/Enterprise**: «Менеджер резервных копий» — коммерческий плагин, доступный только в редакциях Professional и Enterprise.
  2. **Строгие требования к окружению**: окружение БД (версия, настройки чувствительности к регистру и т. п.) должно быть максимально совместимо с окружением, в котором создавалась резервная копия.
  3. **Зависимость от плагинов**: если решение включает коммерческие плагины, которых нет в вашем окружении, восстановление завершится ошибкой.

### Шаги

**Шаг 1: (настоятельно рекомендуется) запустите приложение с образом `full`**

Чтобы избежать сбоев восстановления из‑за отсутствия клиента БД, настоятельно рекомендуем использовать Docker-образ `full`, в котором уже есть все необходимые инструменты.

```bash
docker pull nocobase/nocobase:beta-full
```

Затем запустите сервис NocoBase, используя этот образ.

> **Примечание**: без образа `full` может потребоваться вручную установить клиент `pg_dump` внутри контейнера — это часто приводит к ошибкам.

**Шаг 2: включите плагин «Менеджер резервных копий»**

1. Войдите в систему NocoBase.
2. Перейдите в **`Управление плагинами`**.
3. Найдите и включите плагин **`Менеджер резервных копий`**.

**Шаг 3: восстановление из локального файла резервной копии**

1. После включения плагина обновите страницу.
2. В левом меню перейдите в **`Управление системой`** → **`Менеджер резервных копий`**.
3. Нажмите кнопку **`Восстановить из локальной резервной копии`** в правом верхнем углу.
4. Перетащите скачанный файл резервной копии в область загрузки.
5. Нажмите **`Отправить`** и дождитесь завершения восстановления. Это может занять от нескольких секунд до нескольких минут.

### Примечания

* **Совместимость БД**: это самый критичный пункт. **Версия PostgreSQL, кодировка/набор символов и настройки чувствительности к регистру** должны совпадать с окружением источника резервной копии. В частности, имя `schema` должно быть одинаковым.
* **Соответствие коммерческих плагинов**: убедитесь, что включены все коммерческие плагины, необходимые решению, иначе восстановление будет прервано.

## Метод 2: прямой импорт SQL-файла (универсальный, лучше подходит для Community Edition)

Этот метод восстанавливает данные через прямые операции с базой данных, обходя плагин «Менеджер резервных копий» — редакция Professional/Enterprise не требуется.

### Ключевые особенности

* **Преимущества**:
  1. **Нет ограничений по редакции**: подходит всем пользователям NocoBase, включая Community Edition.
  2. **Высокая совместимость**: не зависит от встроенного инструмента `dump` — достаточно возможности подключиться к БД и выполнить импорт.
  3. **Высокая отказоустойчивость**: если в решении есть коммерческие плагины, которых у вас нет, соответствующие функции не включатся, но приложение сможет запуститься.
* **Ограничения**:
  1. **Нужны базовые навыки работы с БД**: вы должны уметь выполнить `.sql` файл для базы данных.
  2. **Потеря системных файлов**: **все системные файлы будут отсутствовать**, включая шаблоны печати и файлы, загруженные в поля файлов.

### Шаги

**Шаг 1: подготовьте чистую базу данных**

Создайте новую пустую базу данных для данных, которые вы собираетесь импортировать.

**Шаг 2: импортируйте `.sql` файл в базу данных**

* **Вариант A: через командную строку сервера (пример Docker)**

  ```bash
  # Скопировать sql-файл в контейнер
  docker cp nocobase_crm_v2_sql_260223.sql my-nocobase-db:/tmp/
  # Войти в контейнер и выполнить импорт
  docker exec -it my-nocobase-db psql -U nocobase -d nocobase -f /tmp/nocobase_crm_v2_sql_260223.sql
  ```

* **Вариант B: через графический клиент БД (Navicat и т. п.)**

  Подключитесь к базе данных через любой графический клиент (Navicat, DBeaver, pgAdmin и т. п.), затем:
  1. Кликните правой кнопкой по целевой базе
  2. Выберите «Выполнить SQL-файл» или «Выполнить SQL-скрипт»
  3. Выберите скачанный `.sql` файл и выполните импорт

**Шаг 3: подключитесь к базе и запустите приложение**

Настройте параметры запуска NocoBase (например, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USER`, `DB_PASSWORD`), чтобы они указывали на импортированную базу. Затем запустите сервис NocoBase обычным способом.

### Примечания

* **Права БД**: для этого метода нужны учётные данные с прямым доступом к базе.
* **Состояние плагинов**: после успешного импорта данные коммерческих плагинов будут присутствовать, но если соответствующий плагин не установлен и не включён локально, связанные функции не будут видны или доступны — это не приведёт к падению приложения.

## Сводка и сравнение

| Возможность | Метод 1: менеджер резервных копий | Метод 2: прямой импорт SQL |
| :------ | :----------------------- | :--------------------------- |
| **Кому подходит** | Пользователям **Professional/Enterprise** | **Всем** (включая Community Edition) |
| **Простота** | ⭐⭐⭐⭐⭐ (очень просто, через интерфейс) | ⭐⭐⭐ (нужны базовые навыки работы с БД) |
| **Требования к окружению** | **Строгие** — версии БД и системы должны быть максимально совместимы | **Умеренные** — нужна совместимость БД |
| **Зависимость от плагинов** | **Сильная** — отсутствующий плагин приводит к сбою восстановления | **Зависит от функций** — данные импортируются независимо; отсутствующие плагины отключают функции, но приложение работает |
| **Системные файлы** | **Полностью сохраняются** (шаблоны печати, загруженные файлы и т. п.) | **Теряются** (шаблоны печати, загруженные файлы и т. п.) |
| **Рекомендуется** | Пользователям Enterprise с контролируемым стабильным окружением, которым нужна полная функциональность | Тем, у кого нет части плагинов и важны совместимость/гибкость, или пользователям Community Edition, готовым принять потерю функций работы с файлами |

Надеемся, это руководство поможет вам успешно развернуть CRM 2.0. Если возникнут проблемы — пишите!
